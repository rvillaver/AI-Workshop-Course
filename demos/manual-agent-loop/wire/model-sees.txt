THIS is what turn-3.json actually becomes before the model reads it.

The JSON envelope (roles, tool_calls, arguments) is just transport. The API server
unwraps it and flattens the whole conversation into ONE plain-text stream with
little role markers — then the model reads that text and predicts the next tokens.
No hidden state, no memory between calls: everything the model "knows" is the text
below, rebuilt and resent every single turn.

(Illustrative flattening — the exact marker tokens differ per model, but the shape
is real: one growing text transcript in, more text out.)

<|system|>

tools to fetch the recipe, check the pantry, and set timers before answering. Do
not invent recipe details you can get from a tool. When you have enough from the
tools, give the final plan. Keep a short ledger at the top of every reply:
GOAL | DONE | NEXT | OPEN.

[tools available: get_recipe(dish) · check_pantry(items[]) · set_timer(minutes,label)]

Text in, text out. The "agent" is just: append the new text, send the whole
thing again, repeat until the model writes an answer instead of another tool call.
